# 环绕面板闪烁、关闭与动画修复

原因：每次 stats 更新都 replaceChildren 重建指标卡片，而 node 带有入场 CSS 动画，导致动画持续重播。关闭按钮位于 hub 边界之外，原生穿透判定只收集 hub 矩形，未完整覆盖关闭按钮；部分区域也与角色命中矩形重合。

修复：指标卡片、图标、进度条和曲线路径按 metric ID 保留，只更新数据；仅新进入的卡片执行动画。单独收集关闭按钮的可点击矩形，扩大到40px；展开时角色为展示状态，不再拦截关闭按钮。展开约300ms，从原角色位置向外展开；收回约180ms，卡片、连接线和角色平滑收回原位置。减少动态效果时立即切换；快速关闭／重开通过动画代次避免旧的关闭请求覆盖新的展开。

验证：系统环绕专项新增卡片和曲线路径身份保持检查，多次刷新后不重播动画；校验 elementFromPoint 命中关闭按钮、原生点击区域覆盖关闭按钮，并通过 Chromium 鼠标事件点击关闭。该项不等于 Windows 物理鼠标全流程。正式窗口受悬停移动和动态边界影响，工具首次点击未能完成。随后使用同一源码、默认 GPU 的隔离验收窗口，固定边界并保持输入接收，通过 Windows SendInput 实际点击关闭；验收日志为“Real Windows pointer close completed and layout restored”，进程退出码 0。原生透明区域覆盖另由自动化断言验证；这不等于正式环境、实际多屏和混合 DPI 的全流程验收。

最终验证：110 项单元测试通过，运行包专项通过，持续刷新节点保持、动画不重播、鼠标关闭及关闭中重开回归通过。实际运行程序已备份更新并重启。


## 角落展开修复（2026-10-29）

此前原生窗口先直接跳到最终避让位置，渲染层才开始展开，因此角落处会出现明显的一跳。现在先在原位置固定角色并扩充透明视口，再以同一开始时间和 cubic-bezier(.22,1,.36,1) 曲线，约 300ms 同步移动原生窗口、角色和卡片。原生逐帧移动使用 setBounds；本机验收中 setPosition 路径会阻塞，完整边界更新通过。准备阶段用 IPC 确认，不嵌套等待 executeJavaScript。关闭中止原生移动并清理计时器，支持减少动态效果设置。

当前验证：111 项单元测试通过；单屏四个角落的分帧移动、最终工作区边界、中途取消后无残余移动通过，默认 GPU 和禁用 GPU 均通过；系统卡片稳定节点、折线、分页、关闭命中区域、关闭中重开回归通过。运行包四角专项退出码 0，源码与复制文件哈希一致，更新后重启。实际多屏及混合 DPI 仍未进行设备验收；自动断言不等于主观动画流畅度验收。
